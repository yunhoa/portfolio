# 작업지시서 - 심플 통합 문서 (이력서 + 경력기술서 + 자기소개서 한 장)

## 2026.10 최신 통합문서 기준

이 섹션이 최신 기준이다. 아래의 기존 템플릿 설명보다 우선한다.

토스 Server Developer (Product) 3년 이하 지원서에서 사용한 최신 구조가 기준이다.

최신 파일:

```text
wiki/토스_ServerDeveloper_Product_통합본_조윤호.html
```

### 페이지 구성

1페이지:

- 이력서
- 기본 정보 표
- 학력 / 경력 요약
- 자기소개서

2페이지:

- 경력기술서
- 주요 수행 업무
- 주요 프로젝트
- 참여 연구개발 과제

PDF에서 경력기술서는 새 페이지에서 시작해야 한다.

```css
.page + .page {
  break-before: page;
  page-break-before: always;
}
```

### 경력기술서 프로젝트 구조

```text
프로젝트명
참여기간 YYYY.MM ~ YYYY.MM

개요
...

역할
...

기술
...
```

프로젝트명 아래에는 참여기간만 둔다. 기술 스택은 하단 `기술` 줄에 둔다.

## 이 문서를 언제 쓰나

`01-포트폴리오-사이트-작업지시서.md`은 React로 만든 웹사이트다. 프로젝트를 많이 보여주고 싶거나, 웹 개발 역량 자체를 보여주고 싶은 사람에게는 좋지만, 모든 사람이 그런 "제품 랜딩페이지" 느낌을 원하는 건 아니다. 지원 서류는 그냥 담백하게 종이 한 장처럼 보이길 원하는 사람도 있다.

이 문서는 그런 사람을 위한 대안이다. 웹사이트 없이 **이름 → 경력기술서 → 자기소개서가 위아래로 이어지는 문서 한 장**을 만들고, 버튼 하나로 PDF까지 뽑는다. HWP로 뽑던 것과 비슷한 모양이라고 생각하면 된다.

- `01`/`02`/`03`/`04`를 이미 진행했다면 이 문서는 그 답변을 재가공만 한다 (재질문 없음).
- `01` 없이 이 문서 하나만 받아도 완결된 결과가 나오도록 만들어졌다 — 혼자 줘도 동작한다.
- `02`/`03`/`04`(각각 따로 PDF를 뽑는 카드형 문서)와는 다른 결과물이다. 카드형이 마음에 안 들거나, 파일을 여러 개 대신 하나로 받고 싶을 때 이 문서를 대신 써라.

## AI 에이전트 지시사항 (Codex / Claude 등에게)

너는 이 문서를 받아 사용자의 이력서·경력기술서·자기소개서를 한 장짜리 문서로 완성해주는 도우미다.

1. 먼저 사용자가 `01`/`02`/`03`/`04` 중 이미 진행한 게 있는지 물어라. 있으면 그 답변을 그대로 재사용하고, 아래 "입력받을 정보"를 처음부터 다시 묻지 마라. 없으면 아래 순서대로 새로 물어라. 각 질문의 "예시"를 같이 보여줘서 참고하게 해라 (그대로 베끼라는 게 아님을 밝힌다).
2. 지원 회사명과 지원 직무는 반드시 확인해라 (자기소개서 섹션과 파일명에 쓴다).
3. 프로젝트는 몇 개든 반복 가능하다. "프로젝트가 몇 개인지"부터 물어라. 회사 프로젝트인지 개인 프로젝트인지에 따라 문제/판단·해결 대신 배경/구현한 내용으로 쓸지 확인해라.
4. 모든 답변을 받으면 하단 "HTML 템플릿"의 `{{TOKEN}}`을 답변으로 치환해서 `통합문서_{{NAME}}.html` 파일로 저장해라. 브라우저로 열면 상단 `PDF로 저장` 버튼(`window.print()`)으로 바로 PDF를 뽑을 수 있어야 한다.
5. 값이 없는 선택 항목(주소, 논문/자격증/수상, 사진 등)은 해당 줄/블록을 통째로 삭제해라. 빈 라벨만 남기지 마라.
6. 자기소개서 섹션을 채운 뒤에는 `04-자기소개서-포맷-작업지시서.md`의 채용담당자 관점 자가 점검(과장 문구 여부, 실제 경험 근거 여부, 면접에서 설명 가능한지)을 그대로 적용해서 스스로 검토하고, 걸리는 부분은 고친 뒤에 제시해라. 무엇을 왜 고쳤는지 한 줄로 알려줘라.
7. 경력기술서 섹션은 `03-경력기술서-포맷-작업지시서.md`의 작성 원칙(작은 트러블슈팅 하나를 대표 설명으로 삼지 않기, 원인 분석은 확인한 범위를 순서대로 보여주기)을 그대로 따른다.

### 입력받을 정보 (재사용할 답변이 없을 때만, 각 항목 예시 포함)

**1) 기본 정보**
- 이름, 이메일, 연락처, (선택) 주소 — 예: `010-0000-0000`
- 한 줄 포지셔닝 문구 — 예: `Backend Developer · API / Operations`

**2) 학력 / 경력 / 기술**
- 학교명, 전공, 재학기간, (선택) 학점 — 예: `OO대학교 컴퓨터공학과 · 2019.03 – 2025.02 · 3.9 / 4.5`
- 경력: 회사명, 재직기간(총 기간 포함), 직무 한 줄 요약 — 예: `OO소프트 · 2025.01 – 재직 중 (1년 9개월) · Java/Spring 기반 서버 기능 개발 및 운영 시스템 유지보수`
- 보유 기술 (전체 나열, 카테고리 구분 없이) — 예: `Java, Spring Boot, Spring Framework, MyBatis, SQL, REST API, Docker, Nginx`
- (선택) 논문 / 자격증 / 수상 — 예: `정보처리기사 · 2024.11 취득`
- 이력서 자기소개 (선택, 2~3문장) — 예: `저는 Java/Spring 기반으로 SI 프로젝트를 개발/운영해온 개발자입니다.`

**3) 프로젝트 (반복)**
- 프로젝트명 / 소속(회사·기관) / 기간 — 예: `사내 알림 발송 시스템 고도화 / OO소프트 / 2024.06 – 2024.12`
- 한 줄 요약 — 예: `레거시 알림 발송 배치를 실시간 큐 기반 구조로 개선하고, 발송 실패 재처리 로직을 구현했다.`
- 회사 프로젝트: 문제 / 판단·해결 / 맡은 역할 / 결과 / 사용 기술
- 개인 프로젝트: 배경(왜 만들었는지) / 구현한 내용 / 결과 / 사용 기술
- 자세한 질문 순서와 나쁜 예/좋은 예는 `03-경력기술서-포맷-작업지시서.md`와 동일하다.

**4) 자기소개서**
- 지원 회사명, 지원 직무
- 지원동기 (계기 + 지원 이유. 공고 설명보다 내가 기존 서비스와 데이터 흐름을 빠르게 파악해 실제 구현까지 연결할 수 있다는 점을 중심으로 작성)
- 직무역량 (핵심 기술/경험 2~3개 요약)
- 문제 해결 경험 (위 프로젝트 중 하나의 상황 → 문제 → 판단 → 결과를 문단으로)
- 강점 / 일하는 방식 (1~2가지 + 구체적 사례)
- 입사 후 방향
- 자세한 질문 순서와 나쁜 예/좋은 예는 `04-자기소개서-포맷-작업지시서.md`와 동일하다.

## 구조 (문서 안에서 위→아래로 이어지는 순서)

1. **상단**: 이름 + 기본정보 표(학력/경력/보유 기술) + (선택) 증명사진
2. **경력기술서**: 프로젝트마다 요약 → 문제(또는 배경) → 판단·해결(또는 구현한 내용) → 맡은 역할 → 결과 → 사용 기술
3. **자기소개서**: 지원동기 → 직무역량 → 문제 해결 경험 → 강점/일하는 방식 → 입사 후 방향

작성 원칙과 나쁜 예/좋은 예는 이 문서에서 새로 쓰지 않는다. `00-개요.md`의 "품질 기준", `02`/`03`/`04`의 "작성 원칙"을 그대로 따른다 — 이 문서는 같은 내용을 담는 그릇만 다르다.

> 프로젝트가 여러 개면 `.project-block`을 개수만큼 반복하되, 두 번째 블록부터는 위쪽 구분선이 자동으로 생긴다(`:first-child`만 예외 처리되어 있다). 문서가 A4 두 장을 넘어가면 경력기술서와 자기소개서 사이에 `<div class="page-break"></div>`를 넣어 자기소개서를 새 페이지에서 시작하게 해라.

## 체크리스트

- [ ] 이름/연락처/이메일이 정확한지
- [ ] 경력기술서 프로젝트마다 문제(또는 배경) / 판단(또는 구현) / 결과가 들어갔는지
- [ ] 작은 트러블슈팅 하나가 프로젝트 대표 설명이 되지 않았는지 (`00-개요.md` 품질 기준 1번)
- [ ] 자기소개서 각 문단이 경력기술서 내용에 근거하는지, 과장된 문구가 없는지
- [ ] 값이 없는 선택 항목(주소/사진/논문·자격증·수상)이 빈 라벨로 남지 않았는지
- [ ] 남아있는 `{{TOKEN}}`이 없는지
- [ ] 브라우저로 열어 `PDF로 저장`을 눌렀을 때 A4 기준으로 프로젝트/문단이 어색하게 잘리지 않는지 (많이 넘치면 `page-break` 추가)
