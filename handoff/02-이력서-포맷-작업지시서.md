## AI 에이전트 지시사항 (Codex / Claude 등에게)

너는 이 문서를 받아 사용자의 이력서를 완성해주는 도우미다.

1. 먼저 사용자가 `01-포트폴리오-사이트-작업지시서.md`를 이미 진행했는지 물어라. 이미 진행했다면(같은 대화든, 답변을 붙여넣어 주든) 거기서 받은 이름/이메일/학력/경력/기술 스택 답변을 그대로 재사용하고, 아래 "입력받을 정보"를 처음부터 다시 묻지 마라. 안 했다면 아래 순서대로 새로 물어라.
1-1. 아래 "입력받을 정보"를 섹션 단위로 순서대로 물어봐라. 한 번에 다 묻지 말고, 한 섹션씩 답변을 받은 뒤 다음으로 넘어가라. 각 질문에 붙어 있는 "예시"를 같이 보여줘서 어떤 수준/형식으로 답하면 되는지 감을 잡게 해라 (예시를 그대로 베끼라는 게 아니라 참고용임을 밝힌다).
2. 사용자가 "없음"이라고 답한 선택 항목은 최종 문서에서 통째로 생략해라. 빈 칸으로 남기지 마라.
3. 모든 답변을 받으면 하단 "예시 스켈레톤"의 `{{TOKEN}}`을 답변으로 치환해서 완성된 이력서 텍스트를 출력하고, 이어서 하단 "PDF 출력용 HTML 템플릿"도 같은 값으로 채워서 `이력서_{{NAME}}.html` 파일로 저장해라. 텍스트만 주고 끝내지 마라 — 이 HTML을 브라우저로 열면 `PDF로 저장` 버튼으로 바로 PDF를 뽑을 수 있어야 한다.
4. 사용자가 없는 경력/기술/수치를 요청해도 지어내지 말고, 실제로 답변한 내용만 사용해라.
5. 사용자에게 결과를 보여주기 전에, "작성 원칙"과 "체크리스트"를 기준으로 먼저 스스로 검토해라. 특히 경력 한 줄 요약이 기술 나열이 아닌지, 재직 기간 계산이 맞는지 확인하고 **걸리는 부분은 스스로 고친 뒤에 제시**해라. 무엇을 왜 고쳤는지 한 줄로 같이 알려줘라. 값 자체가 불확실해서 판단할 수 없는 경우에만 사용자에게 확인 질문을 던져라.

### 입력받을 정보 (섹션별로 순서대로 질문, 각 항목 예시 포함)

**1) 기본 정보**
- 이름
- 전화번호
- 이메일
- (선택) 주소

**2) 학력**
- 학교명 / 전공 / 재학기간(입학~졸업) / (선택) 학점 — 예: `OO대학교 컴퓨터공학과 · 재학기간 2019.03 – 2025.02 · 학점 3.9 / 4.5`

**3) 경력 (반복, 최근 경력부터)**
- 회사명, 입사년월, 퇴사년월(또는 재직 중), 총 재직 기간, 직무 한 줄 요약 — 예: `OO소프트 · 2025.01 – 재직 중 (1년 9개월) · Java/Spring 기반 서버 기능 개발 및 운영 시스템 유지보수` (아래 "품질 기준" 참고 — 기술 나열이 아니라 무슨 일을 했는지가 드러나야 함)
- 경력이 여러 개면 "다른 경력도 있나요?"라고 계속 물어봐서 전부 받아라

**4) 기술**
- 카테고리명과 카테고리별 기술 목록 — 예: `Backend: Java, Spring Boot, Spring Framework` / `Data·API: MyBatis, SQL, REST API` / `Infra: Docker, Nginx`

**5) 선택 정보**
- 논문 / 자격증 / 수상 (없으면 생략) — 예: `정보처리기사 · 2024.11 취득`
- 이력서 자기소개 3~5문장 (없으면 생략 가능, 원하면 "문장 틀"을 보여주고 채우게 도와줘라) — 예: `저는 Java/Spring 기반으로 SI 프로젝트를 개발/운영해온 개발자입니다. 새로운 시스템을 빠르게 파악하고, 운영 환경에서 실제로 어떻게 동작하는지 확인하는 것을 중요하게 생각합니다.`

---

## 목적

기본정보/학력/경력/기술을 한눈에 훑어볼 수 있는 표준 이력서를 작성한다. 경력기술서·자기소개서의 요약판 역할을 한다.

## 구조

1. **상단 기본정보**: 이름, 연락처(전화/이메일), (선택) 주소, (선택) 증명사진
2. **학력**: 학교명, 전공, 재학기간, (선택) 학점
3. **경력**: 최근 경력부터 역순으로 나열
   - 회사명, 재직기간(입사~퇴사 또는 재직 중, 총 기간 병기), 직무를 한 줄로 요약
4. **(선택) 이전 경력/기타 이력**: 직무와 무관하지만 참고가 될 이력
5. **보유 기술**: 카테고리별로 묶어서 나열 (예: Backend / Data / Infra / Frontend)
6. **(선택) 논문 / 자격증 / 수상**
7. **(선택) 이력서 자기소개**: 3~5문장, 경력기술서보다 훨씬 압축된 요약

## 작성 원칙

- 내용이 없는 항목은 억지로 채우지 않고 통째로 생략한다.
- 경력 한 줄 요약은 기술 키워드 나열이 아니라 "무슨 일을 했는지" 문장으로 쓴다.
- 재직기간의 총 기간(년/개월)은 실제 계산값으로 정확히 표기한다.
- 세부 기술 스택은 이력서보다 경력기술서/프로젝트 카드에서 풀어서 보여준다. 이력서는 훑어보는 용도임을 잊지 않는다.

## 문장 틀 예시 (`{{TOKEN}}`을 답변으로 치환)

- 경력 한 줄: `{{COMPANY}} · {{START}} – {{END}} ({{DURATION}}) · {{ROLE_SUMMARY}}`
- 이력서 자기소개: `저는 {{CORE_STACK}} 기반으로 {{DOMAIN}}을 개발/운영해온 개발자입니다. {{EXPERIENCE}}을 통해 {{VALUE}}을 확인하는 것을 중요하게 생각합니다.`

**`{{ROLE_SUMMARY}}` 품질 기준 (나쁜 예 vs 좋은 예)**

- 나쁜 예: `백엔드/API, 프레임워크 A 연동 및 시스템 유지보수` — 기술 키워드만 나열해서 실제로 무슨 일을 했는지 안 읽힌다.
- 좋은 예: `Java/Spring 기반 서버 기능 개발 및 운영 시스템 유지보수` — 무슨 일을 했는지 한 문장으로 읽힌다. 세부 기술은 여기서 다 풀지 않고 "보유 기술"/경력기술서 쪽에서 보여준다.

## 체크리스트

- [ ] 이름/연락처/이메일이 정확한지
- [ ] 경력 기간 계산(년/개월)이 맞는지
- [ ] 최신 경력이 위로 오는지 (역순 정렬)
- [ ] 기술 스택이 실제 사용해본 것만 있는지 (면접에서 설명 가능한지)
- [ ] 지원 직무와 관련 없는 항목은 줄였는지
- [ ] 남아있는 `{{TOKEN}}`이 없는지 (텍스트 버전과 HTML 버전 둘 다)
- [ ] HTML을 브라우저로 열어 `PDF로 저장` 버튼을 눌렀을 때 인쇄 미리보기에서 툴바가 사라지고 A4 한두 페이지로 깔끔하게 잘리는지
