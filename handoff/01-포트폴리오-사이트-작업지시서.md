# 작업지시서 - React 포트폴리오 사이트 제작

## 2026.10 최신 React 포트폴리오 기준

이 섹션이 최신 기준이다. 아래의 긴 템플릿 설명보다 우선한다.

### 현재 메인 문구

Hero 슬로건:

> 처음 맡는 시스템도 구조부터 익혀 필요한 기능을 만들어왔습니다.

About 제목:

> 운영에서 생긴 문제도 직접 확인해왔습니다

Hero 소개는 SI·연구 과제에서 맡은 개발 범위를 짧게 적고, About은 작업할 때의 방식만 설명한다. 같은 기술 목록과 문제 해결 방식을 두 섹션에서 반복하지 않는다.

> 새 프로젝트에서는 화면에 보이는 결과만 보지 않고 요청이 서버와 DB에서 어떻게 처리되는지 확인합니다. 개발과 운영 환경이 다르거나 외부 연동이 되지 않을 때는 구간을 나눠 원인을 좁히고 필요한 부분을 수정했습니다.

### Hero 기본정보 UI

기본정보 카드는 라벨/내용이 같은 시작선에 맞아야 한다.

- `dl`은 `divide-y`와 border를 사용한다.
- 각 행은 `sm:grid-cols-[5.75rem_1fr]` 구조를 사용한다.
- 학력은 학교·전공을 첫 줄에, 재학기간·학점을 둘째 줄에 배치해 한 줄에 정보가 몰리거나 잘려 보이지 않게 한다.
- 경력은 회사명/기간과 역할 설명을 줄바꿈해서 보여준다.
- 이전처럼 `border-l`만 붙인 세로 나열형은 가로 기준이 없어 보여 사용하지 않는다.
- 상단 네비게이션은 스크롤을 내릴 때 위로 숨고, 스크롤을 올리면 다시 나타나도록 한다. 상단 근처에서는 항상 보이게 하고, 키보드 포커스가 들어오면 표시한다.
- 네비에는 About / Skills / Projects만 두고 Contact는 오른쪽 버튼 하나로 제공해 같은 링크를 중복 표시하지 않는다.

### Projects 카드 기준

- 프로젝트명 아래 메타 줄에는 `참여기간`만 표시한다.

- 개인 프로젝트에는 문제 해결 포인트를 억지로 넣지 않는다.

### 최신 프로젝트 문구 중 주의할 것

MySafety 문제:

> 현장 작업자가 공지사항, 대피소 위치, 작업자 위치 정보를 모바일에서 확인해야 했고, 위치 수집 기능은 WebView만으로 처리하기 어려워 Android/iOS 권한 정책과 네이티브 기능 연동이 필요했습니다.

MySafety 문제 해결 포인트:

> Cordova 기반으로 WebView 화면을 개발하고 REST API를 연동했습니다. 위치 수집은 Background Geolocation과 네이티브 영역을 연결해 처리했으며, Android/iOS 빌드와 스토어 배포 과정에서 인증서, 권한, 로그인 흐름, 앱 실행 이슈를 실제 단말 기준으로 확인하며 대응했습니다.

캡스톤 문제:

> 사용자는 장소 추천, 이동 경로, 소요 시간, 리뷰를 각각 다른 서비스에서 확인해야 했습니다. 또한 같은 장소라도 방문 순서에 따라 이동 시간과 코스 만족도가 달라질 수 있어, 단순 장소 목록이 아니라 실제 이동 가능한 코스 형태로 보여줄 필요가 있었습니다.

캡스톤 해결:

> 백엔드는 Spring Boot와 JPA로 구성하고, 사용자가 선택한 서울의 구와 관심 카테고리를 기준으로 관광지, 음식점, 문화시설 데이터를 조회하도록 만들었습니다. 코스 이동 경로는 TMAP API와 서울시 대중교통 API를 연동해 도보와 대중교통 기준으로 확인할 수 있게 했고, 외부 API 호출이 여러 번 발생하는 구간은 Spring WebFlux로 처리했습니다. React에서는 추천 코스, 지도 경로, 장소 상세 정보, 사용자가 만든 코스 저장·공유 화면을 구성했습니다.

한화오션 안전혁신과제 최신 반영:

- 4개 모바일 모듈과 Spring Framework / MyBatis / Oracle 백엔드 기능을 모두 개발한 범위를 유지한다.
- 교육 동영상 플레이어는 처음 맡은 기능이며, 재생 제한, 화면 이탈 시 중단, 가로 전체 화면과 상·하단 바 처리, 네이티브 연동, Spring Controller Range 응답, 처음 익힌 JMeter로 구성한 동시 사용자 테스트까지 연결해 설명한다.
- MSDS QR은 기본 카메라로 스캔해 로그인 없이 열려야 했으므로 앱 전용 딥링크/Intent 대신 URL 진입을 선택했다. 해당 `.do` 경로만 Spring Security에서 로그인 없이 허용하고 기존 Morpheus 백엔드에서 JSP로 연결한 구현과 이유를 쓴다.
- 문제와 문제 해결 포인트 문구는 `src/data/projects.js`의 한화오션 프로젝트 객체를 최신 기준으로 삼는다.

반도체 제조 디지털 트윈 플랫폼 최신 반영:

- 담당은 React 기반 3D 디지털 트윈 화면 개발과 InfluxDB 설비 데이터 연동·시각화다.
- React Three Fiber로 GLB 공장 모델을 화면에 연결하고, 설비 데이터 매핑과 상태값별 표시를 구현한 내용을 중심으로 쓴다.
- 상태 관리는 Zustand, 조회 관리는 TanStack Query 5.71.10을 사용한 것으로 정확히 표기한다.
- 시계열 데이터를 처음 다루며 일부 설비 데이터가 화면에 제대로 표시되지 않는 부분을 발견했고, Postman으로 요청·응답과 설비별 매핑을 반복 추적해 규칙을 수정하고 3D 화면에서 정상 표시되는 것까지 검증한 경험을 쓴다.
- 설비명, measurement 이름, 상태 코드 같은 내부 식별값은 포트폴리오 본문에서 열거하지 않는다. 시계열 데이터 추적, 매핑 규칙 수정, 화면 검증 흐름으로 설명한다.
- 실제 수행 근거가 확인되지 않은 렌더링 최적화나 성능 개선 주장은 사용하지 않는다.

Slack 업무 자동화 봇 최신 반영:

- 휴가·오늘의 운세·회의·B2B 주간 일정과 현장 체류·RSS 알림을 한 프로젝트로 묶고, 회의실 예약 자동화도 포함한다.
- 매일 오전 9시 휴가자 및 GeekNews 새 글 알림, 회의 시작 10분 전 알림, 매주 월요일 오전 9시 30분 기술 블로그 글 알림으로 주기를 구분한다. B2B 일정은 주간 일정 및 현장 체류 인원 안내로 설명한다.
- 운세 기능은 FastAPI + Ollama 로컬 LLM, PostgreSQL 사용자별 생년월일·수신 동의 설정, 결과 캐싱, 한국 시간 기준 발송 스케줄과 Slack 개인 DM으로 설명한다.
- Playwright 회의실 예약 연동, Slack 명령어, RSS 발송 이력 기반 중복 방지, PM2 프로세스 관리도 구현 내용에 포함한다.
- 현재 프로젝트 데이터는 `src/data/projects.js`의 `Slack 기반 업무 자동화 봇 개발` 항목을 기준으로 한다.

### 검증 / 배포

수정 후 반드시 실행한다.

```bash
npm run build
```

```bash
npm.cmd run build
```

## AI 에이전트 지시사항 (Codex / Claude 등에게)

너는 이 문서를 받아 사용자의 포트폴리오 React 프로젝트를 만들어주는 코딩 에이전트다. 아래 순서로 작업해라.

1. 먼저 이 문서 하단의 코드 템플릿을 **구조와 CSS는 그대로 유지**한 채 그대로 파일로 생성한다. 컴포넌트 구조, className, 레이아웃 로직은 바꾸지 않는다.
2. 템플릿 안에 `{{TOKEN}}` 형태로 표시된 부분은 사용자에게 물어보지 않고는 채울 수 없는 개인 정보/콘텐츠다. **아래 "입력받을 정보" 목록을 순서대로, 한 번에 다 묻지 말고 섹션 단위로 나눠서 사용자에게 질문해라.**
3. 프로젝트(`data/projects.js`)는 몇 개든 반복 가능한 배열이다. "프로젝트가 몇 개인지, 각각의 내용은 무엇인지" 하나씩 물어보고 배열 항목을 그만큼 늘려라. 회사 프로젝트/개인 프로젝트에 따라 `group`, `problem`/`solution` 또는 `background`/`features` 조합이 달라지니 사용자에게 어느 쪽인지도 확인해라.
4. 사용자가 모른다/없다고 답한 선택 항목은 억지로 채우지 말고 필드 자체를 생략해라 (컴포넌트가 이미 값이 없으면 렌더링하지 않도록 되어 있다).
5. 질문마다 아래 "예시"를 그대로 보여줘서 사용자가 어떤 수준/형식으로 답하면 되는지 감을 잡게 해라. 예시를 복사하라는 게 아니라 참고만 하라는 것임을 분명히 밝혀라.
6. 모든 답변을 받으면 `{{TOKEN}}`을 실제 값으로 치환한 최종 파일을 만들기 전에, 아래 "작성 후 스스로 점검" 항목으로 먼저 검토하고 걸리는 부분을 고친 뒤 최종 파일을 생성해라. `npm install && npm run dev`로 확인하는 방법도 안내해라.

### 입력받을 정보 (질문 순서대로, 각 항목 예시 포함)

**1) 기본 정보**
- 이름
- 이메일
- 한 줄 포지셔닝 문구 — 예: `Backend Developer · Java / Spring / API`
- 핵심 소개 2~3문장 (어떤 개발자인지) — 예: `Java/Spring 기반 서버 기능 개발과 운영 시스템 유지보수를 경험한 개발자입니다. 프로젝트마다 다른 시스템을 빠르게 파악하며 Spring Boot, Spring Framework, MyBatis, SQL, REST API 기반 기능을 개발해왔습니다.`

**2) 학력 / 경력**
- 학교명, 전공, 재학기간, (선택) 학점 — 예: `OO대학교 컴퓨터공학과 · 재학기간 2019.03 – 2025.02 · 학점 3.9 / 4.5`
- 경력: 회사명, 재직기간(총 기간 포함), 직무 한 줄 요약 — 여러 개면 반복 — 예: `OO소프트 · 2025.01 – 재직 중 (1년 9개월) · Java/Spring 기반 서버 기능 개발 및 운영 시스템 유지보수` (기술 나열이 아니라 "무슨 일을 했는지" 문장으로)
- (선택) 논문/자격증 등 추가 항목 — 예: `정보처리기사 · 2024.11 취득`

**3) 기술 스택**
- Core 키워드 (자주 쓰는 핵심 기술, 5~7개) — 예: `Java, Spring, MyBatis, SQL, REST API, PostgreSQL`
- Extended 키워드 (경험은 있지만 보조적인 기술) — 예: `PostgreSQL, Docker, React`
- Skills 섹션용 카테고리별 기술 목록 — 예: `Backend: Java, Spring Boot, Spring Framework` / `Data·API: MyBatis, SQL, REST API` / `Infra: Docker, Nginx`

**4) About 문단**
- 소제목 한 문장 (본인 개발 스타일을 압축한 문장) — 예: `요청과 데이터 흐름을 따라 기능을 개발합니다`
- 본문 한 문단 — 예: `Spring Boot 기반 운영 시스템과 Spring Framework 레거시 백엔드를 개발·유지보수하며 MyBatis, SQL, PostgreSQL, REST API 연동 업무를 맡아왔습니다. 처음 보는 시스템도 화면 결과만 보고 수정하기보다 요청이 어떤 로직과 데이터를 거쳐 처리되는지 따라가며 구조를 파악합니다.`

**5) 프로젝트 (반복)**
프로젝트마다:
- 프로젝트명, 카테고리(회사/개인/캡스톤 등), 도메인 라벨, 태그 — 예: `프로젝트명: 한화오션 안전혁신과제 · 카테고리: 회사 프로젝트 · 도메인: Backend / Mobile WebView · 태그: Java, Spring, MyBatis, Morpheus`
- 한 줄 요약 — 예: `Spring Framework 기반 레거시 백엔드와 Morpheus 하이브리드 웹뷰를 함께 맡아 교육이력관리 시스템 기능을 개발했습니다.` (한 가지 이슈가 아니라 업무 범위 전체를 드러내는 문장으로 — 자세한 기준은 `00-개요.md`의 "품질 기준" 참고)
- 회사 프로젝트: 문제 / 판단·해결 / 맡은 역할 / 결과 / 사용 기술 — 예: 문제 `모바일 웹뷰와 Spring 레거시 백엔드를 함께 개발해야 했고, 동영상 업로드·재생 기능은 실제 시청 흐름까지 확인할 필요가 있었습니다.` / 판단·해결 `Morpheus 기반 모바일 화면과 Spring Framework 백엔드 기능을 함께 개발하고, Range 요청에 따라 Spring Controller의 영상 응답 범위를 처리했습니다.` / 결과 `JMeter로 동시 사용자 50명·100명·150명 조건에서 응답시간, 오류 여부, Throughput을 확인했습니다.`
- 개인 프로젝트: 배경(왜 만들었는지) / 구현한 기능·내용 / 결과 / 사용 기술 — 예: 배경 `집에서 쓰던 서버를 외부에서도 안전하게 접근하고 싶어서 구성했습니다.` / 구현 `Nginx Proxy Manager와 DuckDNS로 도메인을 연결하고 방화벽/NAT 규칙을 설정했습니다.`
- (선택) 기관명, 기간, 기여도, 팀 규모, 참고 링크

**6) Contact 섹션**
- 마무리 한 문단 (어떤 경험을 했는지 요약) — 예: `Java / Spring 백엔드를 중심으로 API 연동, MyBatis와 SQL 기반 데이터 처리, 운영 시스템 유지보수, 모바일 웹뷰와 FastAPI 기반 검색 API 프로젝트를 경험했습니다.`
- (선택) 부가 자료(학습 이력 이미지, 포트폴리오 PDF 등)

정보가 다 모이기 전에는 임의로 지어내지 말고, 없는 값은 물어본 뒤 "없음"으로 답하면 그 섹션을 생략해라.

### 작성 후 스스로 점검 (최종 파일 생성 전에)

사용자 답변을 템플릿에 채운 초안을 보여주기 전에, 아래를 스스로 확인하고 걸리는 부분은 먼저 고쳐서 보여줘라. 무엇을 왜 고쳤는지 한 줄로 같이 알려줘라.

- [ ] 경력/프로젝트 한 줄 요약이 기술 키워드 나열이 아니라 "무슨 일을 했는지" 문장인지
- [ ] 프로젝트 대표 설명이 작은 트러블슈팅 하나로 축소되지 않았는지 (업무 범위 전체가 드러나는지)
- [ ] 회사 프로젝트에 `problem`/`solution`, 개인 프로젝트에 `background`/`features` 조합이 맞게 들어갔는지
- [ ] 카드 뱃지/하이라이트가 과하게 늘어나지 않았는지 (`category` + `tags` 2~4개 정도로 제한)
- [ ] 값이 없는 선택 필드가 빈 섹션 제목만 남기고 비어 있지 않은지
- [ ] `{{TOKEN}}`이 하나도 남아있지 않은지

### `src/components/Reveal.jsx` (공용, 수정 불필요)

```jsx
import { useEffect, useRef, useState } from 'react';

function Reveal({ children, delay = 0, className = '' }) {
  const ref = useRef(null);
  const [isVisible, setIsVisible] = useState(false);

  useEffect(() => {
    const element = ref.current;
    if (!element) {
      return undefined;
    }

    const prefersReducedMotion = window.matchMedia('(prefers-reduced-motion: reduce)').matches;
    if (prefersReducedMotion) {
      setIsVisible(true);
      return undefined;
    }

    const observer = new IntersectionObserver(
      ([entry]) => {
        if (entry.isIntersecting) {
          setIsVisible(true);
          observer.unobserve(entry.target);
        }
      },
      { threshold: 0.16, rootMargin: '0px 0px -80px 0px' },
    );

    observer.observe(element);

    return () => observer.disconnect();
  }, []);

  return (
    <div
      ref={ref}
      className={`transition-all duration-700 ease-out ${isVisible ? 'translate-y-0 opacity-100' : 'translate-y-8 opacity-0'} ${className}`}
      style={{ transitionDelay: `${delay}ms` }}
    >
      {children}
    </div>
  );
}

export default Reveal;
```

```jsx
import { useEffect } from 'react';

function ImageModal({ image, alt, onClose }) {
  useEffect(() => {
    if (!image) {
      return undefined;
    }

    const originalOverflow = document.body.style.overflow;
    document.body.style.overflow = 'hidden';

    const handleKeyDown = (event) => {
      if (event.key === 'Escape') {
        onClose();
      }
    };

    window.addEventListener('keydown', handleKeyDown);

    return () => {
      document.body.style.overflow = originalOverflow;
      window.removeEventListener('keydown', handleKeyDown);
    };
  }, [image, onClose]);

  if (!image) {
    return null;
  }

  return (
    <div
      className="fixed inset-0 z-[120] flex items-center justify-center bg-slate-950/88 p-4 backdrop-blur-sm"
      role="dialog"
      aria-modal="true"
      aria-label="이미지 확대 보기"
      onClick={onClose}
    >
      <div className="relative max-h-full w-full max-w-6xl" onClick={(event) => event.stopPropagation()}>
        <button
          type="button"
          onClick={onClose}
          className="absolute -top-12 right-0 rounded-md border border-white/20 bg-white/10 px-3 py-2 text-sm font-semibold text-white transition hover:bg-white/20"
        >
          닫기
        </button>
        <img
          src={image}
          alt={alt}
          className="max-h-[82vh] w-full rounded-lg border border-white/15 bg-white object-contain shadow-2xl"
        />
      </div>
    </div>
  );
}

export default ImageModal;

              className="panel scroll-mt-24 overflow-hidden hover:-translate-y-1 hover:border-blue-300 hover:shadow-xl"
            >
              <div className="border-b border-slate-200 p-5 sm:p-6">
                <ProjectBadges project={project} />
                <p className="mt-4 text-[0.9375rem] font-semibold text-blue-700">{project.domain}</p>
                <h3 className="mt-2 text-xl font-semibold text-slate-950 sm:text-2xl">{project.title}</h3>
                <ProjectMeta project={project} />
                <p className="copy mt-4 max-w-3xl">{project.summary}</p>
                {project.links && (
                  <div className="mt-4 flex flex-wrap gap-2">
                    {project.links.map((link) => (
                      <a
                        key={link.href}
                        href={link.href}
                        target="_blank"
                        rel="noreferrer"
                        className="rounded-md border border-blue-200 bg-white px-3 py-1.5 text-sm font-semibold text-blue-800 transition hover:bg-blue-50"
                      >
                        {link.label}
                      </a>
                    ))}
                  </div>
                )}
              </div>

              <ProjectDetail project={project} />
            </article>
          </Reveal>
        ))}
      </div>
    </section>
  );
}

export default Projects;
```

> 카드 뱃지는 `category`(회사/개인/캡스톤 등) + `tags`(핵심 태그 2~4개) 정도로 제한해라. 여기에 별도 "하이라이트 칩" 줄을 더 추가하지 마라 — 뱃지가 많아질수록 카드가 산만해지고, 어차피 같은 내용이 아래 본문(요약/역할/결과)에 다시 나온다. 카테고리별로 섹션 제목(예: "백엔드 프로젝트", "개인 프로젝트")을 따로 붙이지도 마라 — `data/projects.js`의 `group` 순서로만 정렬하면 카드의 뱃지/도메인 문구가 구분 역할을 충분히 한다.

## 빌드 / 배포

```bash
npm install
npm run dev       # 로컬 개발 서버
npm run build     # 정적 빌드 (dist/ 생성)
npm run preview   # 빌드 결과 미리보기
```

- Windows PowerShell 실행 정책 때문에 `npm run build`가 막히면 `npm.cmd run build`로 실행
- GitHub Pages로 배포할 경우 `dist/`를 `gh-pages` 브랜치로 배포하는 워크플로 구성 권장

## 콘텐츠 작성 원칙

- 실제 하지 않은 기술/성과는 적지 않는다.
- PoC, 검토, 적용, 구현을 구분해서 쓴다.
- 지원 직무와 관련 없는 세부 이슈는 줄인다.
- 자기소개서처럼 과하게 쓰지 않고 경력기술서처럼 담백하게 쓴다.

## 체크리스트

- [ ] 모든 `{{TOKEN}}`이 실제 값으로 치환됐는지 (남은 토큰 없는지 검색으로 확인)
- [ ] 모바일 폭(~400px)에서 카드 문구가 잘리거나 줄바꿈이 어색하지 않은지
- [ ] 프로젝트 카드의 회사/개인 구분에 따라 문제-해결 섹션 노출 여부가 맞는지
- [ ] 이메일/연락처가 실제 값으로 채워졌는지
- [ ] 값이 없는 선택 필드가 빈 섹션 제목으로 남지 않는지
- [ ] `npm run build` 성공 및 배포 후 실제 URL에서 확인
